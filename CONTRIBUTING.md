# Contributing

## Creating a Pull Request

- For all pull requests, target the `dev` branch
- Your title should be short and clear, and your description should describe the changes made, and most importantly your reasoning behind any changes made
- If possible, document your changes wherever appropriate, either in the C documentation or the Lua documentation
- Your PR description may **NOT** be written by an AI, please write it yourself
- Be sure to account for languages! You can read documentation on the system [here](docs/c/sections/lang.md). Only English is required to be filled in for a PR to be merged

## Reviewing Pull Requests

Any help reviewing pull requests is greatly appreciated. Reviewing can range from pointing out very minor issues to constructively criticizing an entire pull request. Whatever the case, present your issues with clarity and respect.

More reviews means a pull request can be merged quicker, so the more the merrier.

## AI Usage

AI usage is allowed so long as the following guidelines are followed:

- You *must* understand what code it has written, and *must* be able to explain your changes. If you can't when asked, the PR will be closed
- You may **not** use AI to write your pr description, please write that yourself. Generated descriptions often describe a whole lot but never explain why. Using a description generated by an AI will get your PR closed

## Documentation

For reading documentation on the project, check out the [C Documentation](docs/c/c.md)!
